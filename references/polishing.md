# 职场化润色规范

上级：[SKILL.md](../SKILL.md)。**所有**用户输入的口语化内容，都必须先按本规范提炼，再进入预览与 Excel。禁止把口水话原样填入表格。

## 1. 润色公式

$$\text{【精准动作动词】} + \text{【业务系统/功能模块】} + \text{【具体手段/工作重心】} + \text{【阶段成果/业务价值】}$$

## 2. 转换对照表

| 用户口语描述 | 职场专业化润色表达 |
| --- | --- |
| "改了结算流水线并发的bug" | 排查并修复订单结算流水线并发冲突异常，优化分布式锁边界校验，确保交易幂等无误 |
| "跟产品对了多租户权限二期" | 参与用户中心多租户权限系统业务需求评审，对齐核心角色鉴权规则与验收标准，完成技术任务拆解 |
| "写了几个接口" | 完成 XX 核心业务模块 RESTful 接口开发与联调，通过接口幂等性验证与单元测试 |
| "线上有点慢，去查了下" | 排查并定位生产环境服务响应延迟瓶颈，优化慢查询 SQL 索引与缓存策略，提升接口响应效率 |
| "写周报脚本" | 封装周报自动化生成 CLI 工具链，打通数据结构校验与模板安全填充，提升填报效率 |
| "下周准备测一测发版" | 推进系统联调与核心业务流回归测试，协同测试与业务团队完成灰度发布前验证 |

## 3. 成果说明自动推导

用户没给详细「成果说明」时，结合工作内容推导一个合理且不越界的成果，例如：

- 完成代码实现并通过自测
- 达成需求一致性结论
- 消除潜在资损隐患
- 完成评审并输出结论

推导结果**必须在预览里让用户看到并确认**，不得静默填入。

## 4. 真实性底线

- 润色的是**表达精度与汇报质感**，**绝不可编造未发生的功能、虚构数据指标、或捏造不存在的外部协作**。
- 用户描述极度模糊时（"弄了一下系统"），**先追问**是哪个系统、什么动作，再润色；一次追问不超过 3 个问题。
- 数字类成果（"降低 40%"）只有在用户说过或可由用户数据推出时才可写；否则改写成定性表述。
